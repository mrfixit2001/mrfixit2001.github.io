1.2.4
- Fixed the final channel-screen playback-return cache so repeated Kodi directory reloads return immediately to the same cached channel/search results instead of consuming a one-use marker and rebuilding on a second reload. Fresh navigation/searches still replace the cached final list, resolver failures invalidate it, and the 30-minute age limit remains.
- Corrected the author spelling to mrfixit2001 throughout the add-on.
- Samsung TV Plus now periodically overlays known seeded channels with the current provider-owned Samsung US lineup for channel names, numbers, and categories. The bundled technical playback seed remains only because Samsung's public consumer lineup does not expose tune-time service IDs/manifest paths for newly added channels.
- Removed the bundled PBS callsign allow-list. PBS now combines its official station service with PBS's own Live Streaming FAQ roster, with an official-station-API fallback if the help page changes or is unavailable. PBS KIDS clear-HLS playback is unchanged.
- Provider coverage documentation now welcomes additional direct-provider requests through mrfixit2001's GitHub profile.
- Reworked genre normalization to use token/phrase boundaries instead of substring matches, added provider-category aliases that can map one source category to multiple StreamDial genres, and added semicolon-separated multi-genre support.
- Pluto and LG channel classification now treats provider channel-level categories as authoritative and uses scheduled-program genres only when channel-level genre metadata is absent. This prevents schedule metadata from permanently placing channels such as Pluto Funny AF into unrelated genres such as Sports.
- Channels with multiple normalized genres continue to appear independently under every applicable genre.

- Provider failures during a snapshot are represented as 0 channels in Browse Providers and no longer produce browse-time provider-offline toasts or stale fallback count estimates.
- All Providers, All Languages, All Genres, individual language/genre counts, and pinned aggregate counts are derived from the exact same snapshot and respect post-de-dup totals when cross-provider de-duplication is enabled.
- Browse by Genre now starts from All Languages, so the full-scope All Genres count represents the same universe as All Providers and All Languages.
- Single-provider scopes remain exempt from cross-provider de-duplication, and playback still resolves fresh at tune time rather than using cached stream details.

1.2.0
- Replaced fanart with the user-selected premium intergalactic/electric StreamDial composition, mechanically fitted to 1920x1080; main and provider icons are unchanged.
- Roku now derives language from Roku station metadata and language tags (including spanish-language) instead of hardcoding every row to English; the Roku catalog cache was bumped so old language metadata is discarded immediately.

Bulk/inline guides are searched directly, while recently fetched per-channel schedules are reused through a 30-minute schedule index to avoid unsafe hundreds-of-request Roku/Plex fan-out.

- Audited runtime endpoints/dependencies: StreamDial contains no custom repository dependency or third-party catalog/playback resolver; provider adapters contact their provider/API/CDN resources directly.
- Preserved opt-in Debug log diagnostics and the StreamDial-only playback-failure toast rate limiting from 1.1.9.

1.1.9
- Added a General > Debug log diagnostics setting (off by default). StreamDial's structured catalog/search/schedule/playback diagnostics, manifest probes, and Widevine preflight details are now emitted only when this setting is enabled.
- Expanded opt-in playback diagnostics to every provider, including a privacy-redacted plan/handoff block and manifest probe for every HLS/DASH handoff plus structured failure details for every provider resolve path.
- Reworked playback-failure toasts so StreamDial never uses Kodi's global notification-window visibility as a suppression flag, rate-limits only its own repeated failure toast across short-lived plugin invocations, and gives Kodi's GUI thread time to commit the toast before signalling setResolvedUrl(false).
- Added a safe built-in Notification fallback only when Dialog().notification itself throws; a successful Dialog submission is never duplicated.
- Roku listings now exclude EPG rows with no viewOptions at all. The supplied logs prove this row class has no cached/live playId and its content proxy returns 404, so it cannot reach /api/v3/playback. Rows with viewOptions but a missing playId are retained for tune-time content-proxy refresh.
- Corrected Roku live-EPG diagnostics so live_epg_stations is the full station count rather than the matched row ordinal, and added bounded station/meta key-shape information for future resolver troubleshooting.
- PBS KIDS playback behavior is unchanged.

1.1.8
- Fixed stale Roku lineup rows surviving upgrades: the Roku catalog cache is now versioned again, the old v2 cache is discarded, and the live lineup cache lifetime is reduced from 30 minutes to 10 minutes.
- Roku channels that are proven unavailable through both the current content proxy and current EPG are temporarily hidden and force a fresh catalog on the next browse instead of remaining as repeatedly failing rows.
- Expanded Roku live-EPG diagnostics to distinguish a channel that is absent from the current lineup from a channel that is present but has no playId, including the number of station rows returned by the live EPG.
- Preserved HLS-first playback and the working DASH/Widevine fallback for Roku channels with a valid playId.
- PBS KIDS remains on its confirmed-working clear HLS route; no PBS playback changes in this release.

1.1.7
- Kept the confirmed-working PBS KIDS clear-HLS path unchanged; PBS KIDS still bypasses Widevine entirely.
- Restored Roku DASH/Widevine fallback behind HLS-first playback now that a compatible Widevine CDM can be used on the target system. FairPlay/SAMPLE-AES Roku HLS therefore falls through to Roku's Widevine DASH rendition instead of being rejected outright.
- Roku now prefers a same-session content-proxy playId before using the disk-cached EPG playId, reducing cookie/CSRF/playId session mismatches across short-lived Kodi plugin invocations.
- Added a live same-session EPG playId lookup after cheaper playId sources fail, followed by one completely fresh anonymous Roku session retry.
- Roku tries both m3u/HLS and MPEG-DASH for failed/incompatible playIds while retaining clear/AES-128 HLS as the preferred path.
- Expanded Roku failure diagnostics to record every session, playId source, media format, HTTP status, manifest compatibility result, cookie/_usn state, endpoint URL, content type, and a bounded/redacted HTTP error body.
- HTTP failures now retain bounded response metadata for provider diagnostics without exposing it in normal user-facing errors.

1.1.6
- PBS KIDS now resolves directly to PBS's clear national HLS feed and no longer invokes Widevine.
- Roku playback is now deliberately HLS-only; DASH/Widevine fallback was removed so a DRM-only Roku channel cannot crash Kodi on affected ARM64 systems.
- Roku playback 404 recovery now bypasses stale EPG playIds and fetches a fresh per-channel playId from Roku's content proxy before retrying.
- Roku performs one final clean anonymous-session/cookie/CSRF refresh before declaring a channel unavailable.
- Roku playback requests now require a real playId and use the current web-client HLS request envelope consistently; the no-playId and compact fallback requests were removed.
- Roku HLS preflight now rejects FairPlay/SAMPLE-AES/non-identity DRM key formats while continuing to allow normal AES-128 HLS.
- Roku playback diagnostics now report the selected HLS resolution path separately from PBS diagnostics.
